# 耳朵 · 真听觉（astrbot_plugin_ear）

让只会读文字的模型**真的听见**语音——不是先转成文字，而是直接听声音本身。

主模型（如 DeepSeek）收到语音只会看到一段 `[Audio]` 占位符，听不到任何东西。
这个插件在生成回复前，把语音交给一个**能听音频的多模态模型**，让它听一遍并说出
「说了什么、什么语气、语速快慢、有没有背景声」，再把这段描述作为**临时上下文**交给主模型。

结果：人格、记忆、说话方式都还是原来那个人，只是多了一只耳朵。

---

## 它和「语音转文字」的区别

| | 语音转文字（STT） | 本插件（真听觉） |
|---|---|---|
| 得到的信息 | 一串文字 | 文字 + **语气 / 情绪 / 语速 / 停顿 / 背景声** |
| 能判断"他在笑" | ❌ | ✅ |
| 能判断"声音在抖" | ❌ | ✅ |
| 能听出背景在放歌 | ❌ | ✅ |
| 依赖 | 任意 ASR | 需要**音频多模态模型** |

例：同一句"我不弄完不睡觉"，STT 只给文字；
本插件给的是「语气着急、带点烦躁或下决心，语速中等，句中有短暂停顿，背景安静」。

## 工作流程

```
QQ 语音消息
   ↓ AstrBot 把语音落到本地（amr/silk/mp3 等）
   ↓ ffmpeg 统一转成 16kHz 单声道 wav（超过 60 秒截断）
   ↓ 调用音频多模态模型（OpenAI 兼容接口，input_audio）
   ↓ 得到一段客观描述
   ↓ 以 TextPart 形式塞进 req.extra_user_content_parts（临时、不进历史）
   ↓ 主模型带着这段描述生成回复
```

设计上的两个关键点：

1. **不动 system_prompt**。动态内容写进 system_prompt 会让前缀缓存每轮失效，
   等于每轮全价重算。所以走 `extra_user_content_parts`，并标记为 temp。
2. **优先级排最后**（`priority=2**31-2`）。这样别的插件（人设/记忆）先写完，
   我们再追加，不会被覆盖。

## 支持哪些模型 / 供应商

只要满足两条就能用：**OpenAI 兼容的 `/chat/completions`**、**支持 `input_audio` 音频输入**。

| 供应商 | 接口地址（`base_url`） | 可用模型（实测） |
|---|---|---|
| 阿里云 DashScope（默认） | 留空即可 | `qwen3-omni-flash`（默认）、`qwen3.8-omni-flash`、`qwen3.5-omni-flash` |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1/chat/completions` | `Qwen/Qwen2.5-Omni-7B` 等 Omni 系 |
| 其他 OpenAI 兼容端点 | 填对方地址 | 任何支持音频输入的模型 |

**注意**：换供应商时，**接口地址和 Key 要一起换**（Key 是跟地址绑定的）。
DeepSeek 系列不支持音频（只收 `text` / `image_url` / `file`），不能当耳朵。

## 配置项

安装后可以直接在 **插件视图** 里改（推荐），也可以改配置文件：

| 配置项 | 说明 | 默认 |
|---|---|---|
| `enabled` | 总开关 | `true` |
| `base_url` | 接口地址，留空 = 阿里云 DashScope | 空 |
| `api_key` | 对应供应商的 API Key，**必填** | 空 |
| `model` | 听觉模型（下拉选择，支持自定义） | `qwen3-omni-flash` |
| `only_owner_private` | 只在私聊、只对主人生效（省额度） | `true` |
| `owner_qq` | 主人 QQ 号 | 空 |

## 可视化视图（扩展功能）

插件带一个视图页 `views/ear/`，在 WebUI 里能：

- **改配置**：开关、接口地址、模型（下拉 / 自定义）、Key（留空不改）、只对主人生效、主人 QQ
- **看听取记录**：每一条的时间、时长、来自谁、听到了什么
- 一键清空记录

记录存在插件数据目录的 `history.jsonl`，最多保留 200 条。

## 依赖

- **ffmpeg**：必须装在系统里（`apt install ffmpeg`），用于把 QQ 的语音格式转成 wav。
- Python 侧只用标准库 + AstrBot 自带依赖，**不需要额外 pip 安装**。

---

## 安全与成本

- 只有**带语音的消息**才会触发，纯文字不消耗额度。
- 默认只在**私聊、且发送者是主人**时生效——群里别人的语音不会被听。
- 单条语音最长处理 60 秒（超出截断），避免烧掉大量 token。
- API Key 存在插件配置里，不写日志、不随插件包分发。

---

## 已知限制

- 需要一把支持**音频输入**的模型 key；DeepSeek 系列不行。
- 不能"实时一直听"——只在收到语音消息那一刻听一次。
- 听不出说话人身份（不做声纹识别）。
- 背景音乐能听出"有音乐、什么感觉"，但通常说不出具体曲名。
